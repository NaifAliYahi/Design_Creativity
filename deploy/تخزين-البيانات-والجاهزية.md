# أين تُحفظ البيانات؟ (مهم قبل 4000+ عميل)

## ملخص سريع

| البيانات | أين تُحفظ | مشترك بين المتصفحات؟ | دائم؟ |
|----------|-----------|------------------------|--------|
| **قوالب JPG الثابتة (1–17)** | ملفات الموقع `public/netcard/` | ✅ للجميع | ✅ مع الرفع |
| **layouts الليبلات الافتراضية** | `bundled-layouts.json` | ✅ للجميع | ✅ مع build |
| **أنواع / محافظ / فلاتر الكatalog** | `catalog-defaults.json` + **`store.json` → `netcardCatalog`** على السيرفر | ✅ فقط إذا السيرفر يعمل والموظف **مسجّل دخول** عند الحفظ | ✅ على السيرفر |
| **أنواع / محافظ (بدون دخول)** | `localStorage` (`mahfazat-netcard-catalog-v1`) | ❌ متصفح واحد | حتى مسح بيانات الموقع |
| **تعديلات الليبلات (موظف)** | `store.json` → `netcardTemplates` + IndexedDB | ✅ مع السيرفر + token | ✅ |
| **تعديلات الليبلات (عميل /design)** | IndexedDB في متصفح العميل | ❌ | حتى مسح بيانات الموقع |
| **قوالب مرفوعة (PNG)** | `store.json` → `netcardCustom` + IndexedDB | ✅ مع السيرفر | ✅ (انتبه للحجم) |
| **عملاء / Excel / استوديو** | `store.json` → `appData` | ✅ مع السيرفر | ✅ |
| **جلسة الدخول** | ذاكرة السيرفر (12 ساعة) | — | ❌ تُفقد عند إعادة تشغيل Node |

**قاعدة البيانات المركزية:** **SQLite** في `web/server/data/app.db` (داخل المشروع).  
عند أول تشغيل يُستورد `store.json` القديم تلقائياً ثم يُؤرشف.  
(حد طلب Express ~80MB للصور base64 — لاحقاً يُفضّل تخزين الصور كملفات.)

---

## لماذا المحافظ لا تظهر في متصفح آخر؟

1. أضفت محفظة **بدون تسجيل دخول** → تُحفظ في **localStorage** فقط.
2. أو السيرفر **غير شغّال** (Netlify static فقط) → لا يوجد `PUT /api/netcard/catalog`.
3. أو السيرفر **قديم** لم يُعد تشغيله بعد إضافة مسار الكatalog.

**السلوك الصحيح للشركة:**  
شغّل `npm run dev` أو سيرفر الإنتاج → `/login` كموظف → **إعدادات القوالب** → أضف محفظة → يُحفظ في `store.json` → أي متصفح/عميل يقرأ `GET /api/netcard/catalog` (بدون دخول) يرى نفس القائمة.

---

## Netlify فقط vs سيرفر الشركة

| | Netlify (static) | سيرفر Node + `store.json` |
|--|------------------|---------------------------|
| 4000 عميل ينزلون بطاقات | ✅ مناسب (CDN) | ✅ |
| كatalog مشترك (محافظ/أنواع) | ❌ إلا بدمج يدوي في JSON و rebuild | ✅ |
| حفظ layouts للعملاء على السيرفر | ❌ | ✅ (موظف) |
| جاهزية 100% مثل Odoo | ❌ ~70% | ✅ ~90% (ملف JSON، ليس DB) |

لـ **4000+ عميل** يُفضّل: **سيرفر الشركة** (أو VPS) + نسخ احتياطي يومي لـ `store.json`؛ لاحقاً ترقية إلى PostgreSQL إذا كبر حجم القوالب المرفوعة.

## اختبار سريع (محلي)

```powershell
# 1) تسجيل دخول
$login = Invoke-RestMethod -Uri "http://localhost:3001/api/auth/login" -Method POST -ContentType "application/json" -Body '{"username":"777465157","password":"1234"}'
$h = @{ Authorization = "Bearer $($login.token)" }

# 2) حفظ كatalog
$body = '{"types":[{"id":"t1","name":"نوع"}],"wallets":[{"id":"w1","name":"محفظة جديدة"}],"templateMeta":{}}'
Invoke-RestMethod -Uri "http://localhost:3001/api/netcard/catalog" -Method PUT -Headers $h -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body))

# 3) قراءة بدون token (مثل عميل)
Invoke-RestMethod -Uri "http://localhost:3001/api/netcard/catalog" -Method GET
```

يجب أن ترى المحفظة في المتصفح الثاني بعد **إعادة تحميل** `/design`.
